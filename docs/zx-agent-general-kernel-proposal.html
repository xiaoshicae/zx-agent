0. 摘要

  • 目标：同一个内核同时支撑三类场景——人机对话（类似 pi）、无人值守任务、被其他程序嵌入。场景差异全部放在内核之外，通过配置、提示词和插件表达。
  • 调研结论：所调研的多个产品采用了“同一引擎 + 多个前端 + 场景配置”的结构，例如 pi 的四种运行模式、Claude Code 的交互式 / --print / Agent SDK / 后台会话、Codex 的 TUI / exec / app-server、Goose 的 recipe、DeepSeek Harness 的 web / headless / sdk / acp profile。
  • 核心方案：保留一个小而固定的内核（模型层、循环层、会话运行时），开放 6 类钩子、一个人机交互接口和 5 个可替换接缝；扩展分三级（配置与提示词、Rust 插件、MCP 服务器）；前端分为 run、chat、acp 和 Rust SDK。
  • 关键取舍：类型化扩展点，而非“一切皆插件”；审批规则按“拒绝 → 询问 → 允许”求值，无人可问时“询问”等同拒绝；上下文压缩永不改写原始历史；命令执行抽象为 Executor，以便放进容器。
  • 实施：分 10 个阶段，逐阶段验证现有 run 的兼容性；D5 若改变默认执行环境，在 P6 单独说明迁移方式并验收。评审结论见第 10 节；阶段计划与进度在路线图中跟踪。

2.2 共性观察

  1. 同一引擎，多个前端。pi、Claude Code、Codex、Goose、dsh 都把“交互界面、无界面、嵌入”做成同一引擎的不同前端。Claude Code 文档明确说明同一组钩子在终端、IDE、桌面和云端会话中都会触发 [R3]。
  2. 场景用“打包好的配置”表达。Goose 的 recipe、dsh 的 profile 与 bundle、kagent 的 YAML 声明式 Agent [R22]，都把提示词、工具和设置打包在一起。
  3. 工具扩展收敛到 MCP。Claude Code、Codex、Gemini CLI、Goose、kagent 都支持 MCP；pi 提供 registerMcpServer。MCP 使用 JSON-RPC 2.0，标准传输为 stdio 与 Streamable HTTP [R23]。
  4. 嵌入协议收敛到 ACP。ACP 规范了编辑器与 Agent 之间的通信 [R24]；Goose 支持 ACP，OpenHands 通过 ACP 运行多家 Agent。
  5. 审批 = 规则 + 人，并且没有人时有确定的回退。pi 无界面时 confirm 返回 false；Claude Code 的 dontAsk 自动拒绝；Codex 的 never 把执行失败直接返回给模型。
  6. 沙箱与审批互补。沙箱减少确认次数（Claude Code 内部数据为 84%），并且必须同时隔离文件系统与网络 [R6]。
  7. 会话日志是唯一事实来源。dsh 的原则是“模型可见即已记录，每次请求都能从日志还原” [R16]；Claude Code 默认把系统提示词按会话记录一次并原样复用，保持请求前缀稳定 [R2]。
  8. 无人值守强调只读、预算与结构化结果。HolmesGPT 只读加 RBAC、输出预算；Claude Code 的 --max-budget-usd；Codex 的 --output-schema。

5. 关键设计

5.1 内核边界

内核 = 模型层 + 循环层 + 会话运行时 + 扩展宿主。内核不包含：具体工具、提示词正文、界面、触发方式（cron、webhook）。

选项代表优点缺点
选择类型化扩展点pi、CodexRust 类型系统能检查；行为可预测；实现量小新增扩展点要改内核代码
不选一切皆插件dsh（Cordis）没有特权内核，可热加载与卸载方案评估：在 Rust 中复刻动态服务注册与卸载需额外管理生命周期；本项目已有类型化接口，当前也没有热加载需求
不选单体加开关—改动最少场景分支散落各处，违背 G1

5.2 会话运行时 AgentSession

由现有 Runner 演进而来：生命周期从“一次任务”变为“一个会话”，可以多次提问。

impl AgentSession {
    pub async fn prompt(&self, text: impl Into<String>) -> Result<RunReport, SessionError>;
    pub fn steer(&self, text: impl Into<String>);     // 运行中插话
    pub fn follow_up(&self, text: impl Into<String>); // 运行结束后再处理
    pub fn abort(&self);                              // 只取消当前运行，会话保留
    pub fn subscribe(&self, sink: Arc<dyn EventSink>);   // 界面、日志、审计同时订阅
    pub async fn set_model(&self, model: ModelRef) -> Result<(), SessionError>;
    pub async fn compact(&self) -> Result<(), SessionError>; // P5 加入
}

语义：同一时刻只有一个运行；运行中调用 prompt 返回 SessionError::Busy，插话须显式调用 steer 或 follow_up。无人值守仍可一行调用：session.prompt(task).await? 取得 RunReport。错误类型及其他细节在 P2 落实。

取舍进程内方法 API + 协议适配器（ACP 等包在外层），而非在内核中实现 Codex 式的提交 / 事件队列（SQ/EQ）。理由：当前只有进程内前端，方法 API 更简单；ACP 适配器可以把方法调用映射为协议消息。何时重新评估：出现多个客户端同时连接同一会话的需求时。

finish_turn每个回合结束时继续或结束（如截断后续写、检查最终答案格式）pi finishTurn；Claude Code Stop
on_event任何事件只读观察：日志、指标、界面pi 事件；EventSink
// 回调返回文字原因；宿主补充 HookError { hook, phase, failure }。
type HookResult<T> = Result<T, String>;

#[async_trait]
pub trait Hooks: Send + Sync {
    async fn on_input(&self, text: String) -> HookResult<String> { Ok(text) }
    async fn transform_context(&self, _: &[Message]) -> HookResult<Vec<ContextEdit>> { Ok(Vec::new()) }
    async fn before_tool(&self, _: &ToolCall) -> HookResult<Decision> { Ok(Decision::Allow) }
    async fn after_tool(&self, _: &ToolCall, output: ToolOutput) -> HookResult<ToolOutput> { Ok(output) }
    async fn finish_turn(&self, _: &TurnSummary<'_>) -> HookResult<TurnDecision> { Ok(TurnDecision::Default) }
    async fn on_event(&self, _: &AgentEvent) -> HookResult<()> { Ok(()) }
}
pub enum Decision { Allow, Deny(String), Ask(String) }

组合规则：按注册顺序执行；多个 before_tool 的结果取最严格者（Deny > Ask > Allow）；策略类钩子出错按拒绝处理（fail closed），观察类钩子出错只产生不递归的 hook_failed 诊断；单次回调默认超时 5 秒，可单独覆盖。panic 与超时按失败处理，取消会中断等待。输入、上下文、回合钩子失败结束运行且不重试 provider；工具前置失败变成拒绝结果，后置失败丢弃原始输出。

持久化约束：on_input、transform_context 的变换结果必须先以追加消息、context_edit 或 P5 的 compaction 条目记录，写入成功后才请求模型；不能只在内存中改写上下文。P1 的 ContextEdit 明确表达追加、替换文本或省略，整份计划先校验；不能改写或省略 system 消息，也不能以文本替换抹掉工具调用。逐项写入失败时立即取消，保留已写入条目，不请求模型。

ContinueOnLength 与 RedactSecrets 位于 src/extensions.rs。前者通过 finish_turn 续写；后者在 after_tool 中过滤显式配置密钥的完整字面值，CLI 默认配置认证 key。未知密钥、编码变形、用户输入、模型输出与工具参数不在此过滤范围。

5.4 人机交互与审批

规则：按工具名和命令前缀匹配，求值顺序为 deny → ask → allow，首个匹配生效（与 Claude Code 一致 [R5]）。P1 的 RulePolicy 支持工具名与字面命令前缀匹配，同级按注册顺序，无匹配时拒绝；命令前缀匹配不是 shell 解析。配置文件叠加在 P4 实现，目标是 deny 规则只增不减，后加载的配置只能收紧。

#[async_trait]
pub trait Interaction: Send + Sync {
    async fn confirm(&self, request: &ApprovalRequest) -> Result<Approval, String>; // 允许一次 / 本会话允许 / 拒绝
    fn notify(&self, text: &str) {} // 可选通知
}
pub struct NoHuman; // confirm 恒为拒绝：无人值守

审批默认超时 120 秒。失败、panic、超时或取消均拒绝。AllowSession 只允许同一 Runner 中完全相同的工具名与参数，仍须每次通过策略，可用 clear_approvals 撤销；授权不持久化。阻塞回调无法被合作式超时抢占。

5.8 上下文管理

  • 原始历史只追加、不改写。压缩以追加条目表达：compaction 条目记录“保留的第一条条目”与摘要（沿用 pi 的结构）。
  • 摘要分两部分：“环境事实”每条附原始条目出处；“推断与计划”单独列出，供模型区分（依据 [P14]）。
  • 触发：上下文达到阈值时自动触发，或在 chat 中用 /compact 手动触发；无人值守的短任务默认关闭（依据 [P13]）。
  • 工具侧预算：截断、分页、大结果写入文件只返回路径（参考 HolmesGPT 的输出预算 [R19]）。
  • 提示词更新：按段落记录、变化只追加（已实现）。发送时默认 collapse，提示词变化会影响既有前缀的缓存复用；服务端支持且模型、工具等发送配置不变时，可选 inline 保持此前的请求前缀，实际缓存命中由服务端决定。
取舍阈值触发的摘要压缩作为内置扩展；模型自管上下文 [P15] 作为可选扩展，不进内核；不做“摘要的摘要”（依据 [P11]）。

5.9 执行环境与安全

  • Executor 接缝：bash 等工具通过 Executor 执行命令。先实现 LocalExecutor（现有行为）与 ContainerExecutor（docker exec）；后续可加 SSH、kubectl exec。这与 mini-swe-agent 把 subprocess.run 换成 docker exec 的思路一致 [R18]。
  • OS 级沙箱（Linux 的 bubblewrap + seccomp、macOS 的 Seatbelt，参考 Codex [R9]）作为后续的 Executor 实现，不在本期。
  • 无人值守候选方案（D5 待定）：只读工具集 + 命令白名单 + 容器隔离。是否默认强制容器尚未决定；当前命令仍在本机执行。文件系统与网络需要同时约束 [R6]。
  • 在线排障的前提：完全禁网只适用于离线任务；查询 Kubernetes、Prometheus 等远端 API 需要受限网络访问和相应凭据。P6 实施前须列出目标地址与权限范围并评审，无网络容器的测试不代表在线排障已验收。
  • 不可信数据：工具输出、网页内容不能扩大权限；无人值守运行中工具集固定，不因模型输出新增工具或放宽规则 [P9]。
  • 密钥：沿用现有措施（删除 bash 子进程中的 key 环境变量、Unix 上新建会话文件权限 0600，打开已有文件不修改权限），新增 after_tool 脱敏扩展。

5.10 持久化与恢复

  • Tool trait 增加 effects()：只读或有副作用。规则与恢复逻辑都依赖它（如只读工具在计划模式下可直接执行）。
  • 有副作用的工具执行前先追加 tool_call_started 条目。进程崩溃后恢复时，“已开始但无结果”的调用标记为结果未知，由模型或人决定是否核对，不自动重放（依据 [P17]）。当前实现给缺失结果补“No result provided”，会让模型误以为调用没有执行。
  • 会话格式随新条目的首次落盘升级：P5 引入 compaction 时先升级，P6 引入 tool_call_started 时再升级；每次都兼容读取更早版本，不能延后到 P6 才处理 P5 的格式变化。
