# 02 所有权与借用

借用检查报错，通常说明数据的所有权和流向没有设计清楚。修复方向是改设计，不是用运行时手段绕过去（红线 1）。

## 遇到借用错误时，按顺序尝试

前一步能解决，就不进入下一步：

1. 读完整报错，包括 `note:` 和 `help:`，找出是哪两个借用在冲突、各自的范围。
2. 缩短借用：先取出需要的值再修改，或者调整语句顺序。
3. 拆分借用：分别借用不同字段（`let Self { items, log } = self;`），或者用 `split_at_mut`。
4. 移动所有权：把值传进去、把结果返回出来；用 `std::mem::take`、`Option::take` 从 `&mut` 中取出值，而不是 clone。
5. 用索引或 id 代替长期持有的引用。树和图不写成 `Rc<RefCell<Node>>`；本项目的会话树就是 `HashMap<String, usize>` 加 `parent_id`（`src/session.rs`）。
6. 数据确实需要共享所有权时，才用 `Arc`，并在注释里说明前 5 步为什么不适用。

同一个错误改了两次还没解决，就停下来重新审视数据结构，不要反复"改一下再编译试试"。

## 常见的错误修法

| 错误修法 | 问题 | 正确做法 |
|---|---|---|
| 字段改成 `Rc<RefCell<T>>`，为了在 `&self` 方法里修改 | 借用错误变成运行时 panic；不是 `Send`，不能交给 `tokio::spawn` | 需要修改，就要求 `&mut self` |
| `for item in self.items.clone()`，消除遍历时修改的冲突 | 只为了编译通过就复制整个 Vec | 拆分借用，或者先算出结果再统一修改 |
| 加 `'static` 或用 `Box::leak` 消除生命周期报错 | 把要求转嫁给调用方；`Box::leak` 每调用一次泄漏一次 | 返回拥有所有权的值 |
| 默认就用 `Arc<Mutex<T>>` | 所有共享状态都包一层锁 | 单一所有者加 channel；计数器、标志位用原子类型 |
| 为了满足 `tokio::spawn` 加 `Arc` 和 `.clone()` | 并发通常不需要 spawn | 见 04 中 `tokio::spawn` 一条 |

`.clone()` 只在三种情况下合理：开销很小（`Arc::clone`、`Copy` 类型、很短的字符串）；值要移交给独立的生命周期（spawn 的任务、channel 的另一端）；确实需要两份独立的副本。理由只是"不 clone 编译不过"时，回到上面的顺序。
